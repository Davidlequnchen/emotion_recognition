# 研究方向：什么样的上下文能帮助音频大模型判断情绪？

[related_work.md](related_work.md)、[venues.md](venues.md)。[experimental_design.md](experimental_design.md) 保留了旧设计，执行前应核对本页的新范围。

目前采用 16 个数据集：原 13 个已有 SER 基线，DailyTalk、EmotionTalk、MultiDialog 已下载核验并接入 loader，待跑基线。有 5 个专用 SER 模型；三个开源音频 LLM 是 Gemma 4 E4B、Qwen2.5-Omni 7B、Qwen2-Audio 7B。
API 模型属于后续可选验证。只使用获准用于相应实验的公开研究数据，不使用公司数据。

## 1. 我们现在真正想问什么？

**同一条声音，给出不同的额外信息后，模型的情绪判断会怎样变化？这种变化是否合理，是否接近人在相同信息下的判断？**

“音频 LLM 在 SER 上表现较差”“增加几个示例没有提升”已有相关工作。再增加模型或数据集数量，未必回答新的问题。
我们优先研究两种具体的额外信息：

| 信息 | 通俗解释 | 与普通 few-shot 的区别 |
|---|---|---|
| **说话人声音参照** | 先听这个人平静时怎样说话，再判断当前句 | 不是随便给几个陌生人的例子，而是给当前说话人的声音基线；若注明 neutral，就使用了参照标签 |
| **真实对话历史** | 先了解当前句之前发生了什么，再判断当前句 | 历史属于目标所在的会话，不给历史情绪答案；不等同于带标签 demonstrations 的 ICL |

两者都通过输入提供额外信息，但回答的问题不同。A 保留 in-context learning 这条线，同时将**带标签的参照**与**不带情绪标签的历史**分开报告。
研究目标是听者感知到的表达情绪，不推断无法直接验证的人物内心真实状态。

### 当前 research questions

| RQ | 问题 | 主要证据 |
|---|---|---|
| **RQ1：什么信息有帮助？** | 同说话人参照、真实过去对话和文字历史，分别能改善什么样的目标句？ | A1 / A2 的配对输入条件；UAR、macro-F1、各类召回和预测变化 |
| **RQ2：改变是否合理？** | 人在获得上下文后会不会改判？模型是否作出相应变化，而不只是变得更自信或少答 neutral？ | 同一目标音频、相同证据条件下的多人投票；新标注尚未采集 |
| **RQ3：结果能否推广？** | 发现是否依赖某几个例子、某个说话人、某段电视剧或某个模型？ | 独立说话人/对话、重复参照选择、第二个语料及不同模型的验证 |
| **条件性扩展：如何改善？** | 已确认的失败能否通过优化指令改善？教练能听到错例是否有额外价值？ | B：同一教练有/无音频、相同搜索预算和独立测试 |

零样本基准是起点，C / D 是结果可信度检查，E / G 帮助解释判断依据和标签。**它们不需要各自成为一项主要贡献。**

## 2. A1：这个人平静时怎样说话，能成为有用的参照吗？

有人平常就说得高、快、响；另一个人声音稍微提高，可能已经是在激动。我们检验的假设是：
**知道当前说话人的声音基线，可能比听几个陌生人的情绪例子更有用。** 这是假设，不预定它一定有效。

先从 CREMA-D、MCAE-SPPS 等有受控录音和说话人身份的数据中选一个做 pilot。先核对足够的参照录音、标签质量和句子安排，
不直接展开原先五语料的大网格。MELD 虽有 neutral 标签，但没有为每个角色专门录制的统一平静参照，因此不是这个实验最方便的起点。

### 最小配对条件

固定同一批目标音频和候选类别，只改变参照：

| 条件 | 输入 | 用途 |
|---|---|---|
| S0 | 目标音频 | 基线 |
| S1 | 另一说话人的一条 neutral 参照＋目标音频 | 检查增加一个带标签声音的作用 |
| S2 | 当前说话人的一条 neutral 参照＋目标音频 | 与 S1 比较说话人匹配的价值 |
| S3 | 只给相同 neutral 文字提示，不放参照音频＋目标音频 | 检查收益是否只来自标签提示 |

参照尽量匹配句子、时长和录音条件；支持句与目标句不重合。使用几个预先固定的参照选择，报告结果范围。
如果扩展到多个情绪示例，再加入相同音频与标签数量的配对打乱、仅标签和顺序对照。示例更多不保证更好。

**“同说话人”需要单独说明。** 选择 prompt、规则和超参数时仍需独立说话人；正式 A1 中，测试说话人的另一条录音是明确允许的
校准输入。支持录音与目标录音必须分开，不根据目标情绪挑参照。这不能被称为完全没有说话人信息的零样本实验。
如果用 gold 标签挑 neutral 参照，就要如实报告这项额外标注条件。

**避免答案泄露。** 不构造“其他情绪都说目标句，只有正确情绪换句子”的参照集；不让句子是否匹配透露答案。
如果未来做情绪嵌入检索，应同时报告“直接采用检索标签”的简单基线。检索和多数投票暂不作为本轮必做项。

### 什么结果值得继续？

- S2 稳定优于 S1 / S3，且在新说话人或第二个语料复现：支持说话人参照有额外价值。
- 只有 neutral 预测增加，非 neutral 类别没有改善：需要检查标签倾向，不直接称情绪识别提升。
- 没有明确收益：结合效应区间判断是否排除了有实际意义的收益；“不显著”本身不等于无效。

说话人个性化 ICL 已有相关工作，例如 [Ihori et al., ASRU 2025](https://arxiv.org/abs/2509.08344)。
现成冻结 LLM 与专门训练系统的设置差异值得核对，但不能据此直接宣称首次。

## 3. A2：真实的过去对话，能帮助理解当前这句话吗？

这条线先用 MELD，因为本地有逐句音频，以及 `Dialogue_ID`、`Utterance_ID`、`Speaker` 和转写。
它来自美剧 *Friends*，具有会话结构，但仍是编剧和演员表演，不能作为完全自发自然交流的代表。

### 一个本地数据中的具体例子

| MELD 测试集位置 | 内容 | 现有标签 |
|---|---|---|
| dialogue 252，utterance 0 | Chandler 正在抱怨 Ross 不要再重复 | anger |
| dialogue 252，utterance 1 | Ross 回答 “Fine!”（约 1.1 秒） | anger |
| dialogue 275，utterance 0，另一段录音 | Ross 说 “Fine.” | neutral |

这说明同一个词不能唯一确定情绪。后两条是不同录音，**不能据此把标签差异归因于上下文**。
实验要固定 `dia252_utt1.wav` 这条声音，再改变它之前提供什么：

| 条件 | 输入 | 用途 |
|---|---|---|
| H0 | 只有目标音频 | 单句基线 |
| H1 | 真实过去轮次的音频＋目标音频 | 检查真实音频历史的作用 |
| H2 | 相同历史的文字转写＋目标音频 | 检查收益能否由语言内容解释 |
| H3 | 时长/轮次数接近、来自其他对话的历史音频＋目标音频 | 检查历史相关性与对无关信息的敏感性 |

本轮先固定一个短历史窗口，例如最近一轮；是否增加到三轮，需在设计集上决定。
每个输入明确标记说话人与目标轮次，要求**只判断目标句**；只给过去，不给未来，不给历史或目标的 gold emotion。
同一目标在所有条件下使用相同音频、候选类别和计分规则。H3 是敏感性检查，不自动等于“错误答案测试”。
优先使用一致的匿名说话人标记，避免只有历史条件额外暴露角色姓名或剧集知识。如果目标标记改变了 prompt，H0 也需采用配套格式重新计算；不能直接混用不同格式的基线缓存。

**四个条件分别说明什么？** H0 是无历史对照；H3 则是无关对话的历史，不是又一个无历史条件，也不等同于打乱同一段历史的顺序。
H1 相对 H0 衡量音频历史的总作用，包含语义、语气、节奏、说话人与背景。H2 相对 H0 检查只有历史文字是否也能提供帮助。
H1 与 H2 的差异不能直接命名为“纯声学贡献”：人工转写通常更清楚，两种模态的处理方式也不同。
因此，若 H2 能复现 H1 的收益，支持的是“文字历史足以解释该收益”，不是“模型完全不用声音”。若后续需要更强的声学检验，可加“相同历史文字＋原历史音频＋目标音频”，与 H2 比较；第一轮不扩大为完整网格。

### “人加了上下文会改判”，现有标签能直接证明吗？

不能。人听一句 “Fine” 时，可能把它理解成接受，也可能是不耐烦。知道它是在回应责备后，解释可能改变；也可能声音本来就足够明确，
加历史没有作用。这是需要测量的变化，不能预设。

MELD 有一套基于视频和转写的情绪标签，没有同一目标在 H0 / H1 / H2 等条件下的独立人类投票。
可以先测模型对原标签的表现，但仅凭涨分，不能说明模型更符合人在同条件下的感知。

若 pilot 值得继续，建议为一小批目标采集两条件或多条件投票：不同标注者组看到相同目标、不同证据，问题保持相同，
保留每类票数。抽样覆盖多个对话和情绪，包含普通句与短回应，不只挑模型错例。人数、样本量和预算还需决定。
评估时看模型变化与人的变化是否一致，也看人在各条件下是否仍有分歧。每种条件用其对应的人类票数作参照，
不强迫所有条件共用原来的单一硬标签；避免让先听过历史的同一个人再假装进行无历史判断。

更换历史有时确实会改变合理的情绪解释；**模型改变答案不自动意味着被误导**。要结合人类同条件判断，区分合理改判和无关信息干扰。
标签也不等于人物不可观察的真实心理状态。

### 数据与公平比较的边界

- 当前本地只有 MELD 官方 test；可用于接口检查和探索。不要反复用其结果选择 prompt 或历史窗口，再称完全未接触的最终测试。
  正式设计应另备 train/dev 或独立设计集，并在未用于设计的数据、另一语料上验证。
- IEMOCAP 和 MSP-Conversation 目前只是 [survey 候选](../../emotion_recognition/docs/datasets_survey.md)，未下载、未加入当前 13 个评测集。
  IEMOCAP 更接近现有逐句类别任务；MSP-Conversation 主要是连续 V/A/D 轨迹，需要另定任务，不能硬转成官方七类标签。
  DailyTalk、EmotionTalk 均已全量核验并保留，分别适合英语和中文过去轮次 pilot。DailyTalk 的公开 ECSS 类别逐条与原始文本标签一致，不能当作第二套独立听感金标准。EmotionTalk 可用双人历史目标 18,306 条，test 为 1,830 条；使用音频 gold、仅完整过去轮次，并注意 val/test speaker ID 重叠。RESD 仅查元数据、暂不下载。具体状态见 survey 第 3b 节，均未自动加入正式评测。
- 原有五个 SER 只看目标音频。给 LLM 增加历史后，可以研究它自己的变化，但不能直接宣称在等信息条件下胜过这些 SER。
- 不同角色、背景笑声、音乐、片段长度、类别比例及可能的剧集熟悉度，都可能影响 MELD 结果；需要分层并在第二种会话来源复现。

## 4. 先做多小的 pilot？怎样决定是否扩大？

| 步骤 | 做什么 | 通过后再做什么 |
|---|---|---|
| 0 | 核对模型能读取多条音频、区分历史与目标，目标位置改变后仍能回答可核对的问题 | 修好输入后才解释情绪结果；processor 接受多音频不等于模型用对了 |
| 1 | MELD 三模型的完整单句基线，2,608 条；检查新协议、无效回答、UAR / macro-F1 / 混淆 | 确定可复用的 H0；不因某个指标领先就断言对话优势 |
| 2 | A2 在跨多个对话的小样本上比较 H0–H3；另选一个受控语料小样本做 A1 的 S0–S3 | 样本量先作为技术和现象探索，不代替正式统计设计 |
| 3 | 决定是否采集小规模同条件人类投票，或改用更适合该问题的数据 | 即使模型没提升，人类是否受帮助仍可能有解释价值 |
| 4 | 挑一个问题扩大，加入独立数据和不同模型验证 | 只有出现清楚失败模式，才优先考虑 B 的改善实验 |

**当前实现状态（2026-11-09）。** `config/evaluation.yaml` 已限定本机 MELD＋三个开源 LLM，`limit: null`，依次运行。
现有 `evaluate.py` 仍是**每条音频独立输入**。另有 `scripts/evaluation/context_pilot.py` 已实现 EmotionTalk train 的 H0–H3、多音频边界、独立缓存和逐目标配对分析；固定 240 条来自 197 段对话。按用户要求仅 prepare，尚未推理。S1–S3 说话人参照仍待实现。详见[运行与解释](../../emotion_recognition/docs/context_pilot.md)。
运行单句配置并不等于完成上下文 pilot；新增条件应另设实验身份，避免覆盖或误复用基线。

时间以本次运行和多音频试跑实测为准；旧的 few-shot 全网格时间估算不再作为排期依据。

### 下一轮先做什么（2026-11-09 预检）

MELD 上 Omni 的 Accuracy / UAR / macro-F1 为 **51.27 / 43.45 / 40.43%**，三项点估计均高于当前五个 SER。Gemma 和 Qwen2-Audio 的 macro-F1 为 30.86 / 29.35%，neutral 预测率却分别为 54.45 / 10.58%。这些是模型差异的线索，尚未检验上下文作用或统计显著性。全答 neutral 的 Accuracy 为 48.16%，所以不单看 Accuracy。

Qwen2-Audio 的本次 Instruct checkpoint Accuracy 为 30.71%，技术报告的 MELD 数值为 55.3%。模型版本、prompt 和输入/计分设置未完全对齐，扩大前应做官方输入格式的小规模 sanity check，不直接把差异解释为能力下降。[技术报告](https://arxiv.org/html/2407.10759v1)

| 数据与范围 | 条数 | 用法 |
|---|---:|---|
| EmotionTalk train 中的开发目标 | 先 200–300 条 | 先用 Omni 检查 H0–H3 接口、速度和现象 |
| EmotionTalk 官方 test | 1,929 | 设计冻结后的单句基线；已审计规则下 1,830 条可做双人历史配对 |
| DailyTalk validation | 1,197 | 开发和流程验证；fear/disgust/anger 仅 1/3/4 条，不作稳定七类结论 |
| DailyTalk 正式 holdout | 待固定 | 公开文件没有官方 test；先按对话冻结划分，再评测 |

EmotionTalk 的 validation/test 共享部分 speaker IDs；若要说话人独立设计，开发目标应从 train 选择。新历史边界冻结后，重新计算四条件共同目标交集：不能拿全 test 的 H0 分数直接与较小历史子集的分数相减。DailyTalk 有一组跨两个 train 对话的完全相同 WAV；新建划分时将这两个对话放同组或预登记去重。

**规模与时间。** 本机 MELD 推理为 Gemma 27.3、Omni 31.0、Qwen2-Audio 43.8 分钟。按条数/总时长两种方式外推，三模型两套全量 H0 约 28–33 小时；EmotionTalk test 约 1.3–1.8 小时，DailyTalk validation 约 47–48 分钟。这些不是置信区间或完成保证；先用开发小样本测实际吞吐。

**实现先过关，再解释结果。** 三个新 loader 和 EmotionTalk 的 Omni H0–H3 已接入，轻量边界/缓存检查通过；真实推理尚未运行，不能称实验验证完成。第一轮先用最近一个完整过去轮次，`history.end <= target.start`，按开始时间排序，始终保留完整目标。EmotionTalk 当前 CSV 的三轮列表按结束时间排，部分历史互相重叠，不能直接作为开始顺序串接。其 test 中 135/1,830 组三轮历史＋目标超过 30 秒；Gemma/Qwen2-Audio 会截断，必须先给完整目标留预算，再缩减较旧历史，跨模型采用相同规则。

冻结目标/历史 IDs、匿名 speaker 标记、目标边界、转写清理、历史顺序和长度预算；将这些及 condition/seed 纳入缓存身份。不给 history emotion/intensity、caption 或目标 gold。可在开发小样本加“只给目标转写”作为辅助检查。接口和提示冻结后，先跑新语料单句基线，再在共同目标集比较上下文条件，有信号后扩展模型和独立对话。本轮没有启动新推理。

**演员数据与合理改判分开验证。** MELD 是影视表演，DailyTalk 是剧本对话，EmotionTalk 是演员主题即兴，都不能称完全自发生活录音。换数据集也不能替代同目标、不同证据下的独立人类投票。“Fine”可能仅凭声音已经很好判断；是否因历史改判，需要实际测量。公开 gold 可用于报告任务得分，不能直接证明模型变化更符合人的感知。

## 5. B：明确失败以后，GEPA 能不能帮助改善？

GEPA 会让“教练”读当前指令、模型答案和反馈，再提出新指令；模型权重不变。
它是已有优化方法（[GEPA, ICLR 2026](https://arxiv.org/abs/2507.19457)）。把它用于 SER，本身不足以自动成为主要贡献。
音视频问答已有相关接口研究（[AVQA interfaces](https://arxiv.org/abs/2610.20085)，目前标为 submitted to ICASSP 2027，非已核实录用）。

更具体的问题是：**教练只读错题文字，与还能听错例，学到的规则是否不同？哪一种能迁移到新对话或语料？**

| 条件 | 教练获得的信息 |
|---|---|
| B-text | 指令、预测、训练真值、同一份转写与结构化反馈 |
| B-audio | 与 B-text 完全相同，再加错例音频 |
| 改写对照 | 相同候选/评测预算下的普通改写搜索，用来检查收益是否需要反思过程 |

B-text 与 B-audio 使用**同一个多模态教练模型**，只改变音频是否可见。控制反馈条数、搜索预算、候选选择和验证集；记录调用数与输入开销。
反馈和 prompt 选择不能使用正式测试标签。教练无论是否听到音频，都不能直接读取目标测试样本的答案。

先小预算试跑，再检验持出说话人/对话和跨语料迁移。若只改善验证集或只改变 neutral 比例，不能称学到了通用声学判断规则。
优化也可能改变模型处理输入的方式，不应简单断言“prompt 只能改最后输出，不能影响表示”。本轮不预设 GRPO、LoRA 或大规模 B 网格为必做。

| 工作 | 已覆盖的内容 | 对本计划的约束 |

| [AVQA interfaces](https://arxiv.org/abs/2610.20085)，投稿 ICASSP 2027 | GEPA / COPRO 与多模态系统反馈接口 | B 的价值应来自具体反馈问题和可迁移结果，不是工具组合 |

## 7. 支持分析：每项只回答一个必要问题

### 0. 基准：起点是什么？

保留已完成的五个 SER 结果和进行中的音频 LLM 结果。候选标签与计分规则保持一致，报告 Accuracy、UAR、macro-F1、各类召回和 neutral 率。
LLM 不是所有指标都同时领先或落后；MELD 的某个指标反转只能作为线索。旧 prompt / 旧协议结果保留，但不能混入当前正式表格。

### C. 训练来源：模型公开声明见过什么？

本项目将直接训练和上游间接使用均计为“见过”：包括预训练、seed 微调、教师伪标签链与明确的开发校准。图中均用同一种训练斜线；具体方式只保留在来源记录中，不将间接使用排除在已见组之外。

记录训练语料、版本、划分、骨干和伪标签来源，分清**直接训练使用**、**间接教师影响**、**可能开发关联**、**测试文件泄漏**和**暂无对应证据**，来源见
[模型调研](../../emotion_recognition/docs/models_survey.md)与[分级来源审核](../../emotion_recognition/docs/training_provenance.md)。
同语料参与训练并不等于测试文件泄漏；seen/unseen 组成绩差异还混合语言、标签、录音和领域差异，不能直接解释为记忆。
公开清单没有列出某语料，也不是从未接触的证明。数据发表晚于模型发布是时间线线索，仍要核对录制、获取与模型版本。
模型间的家谱或伪标签关系可解释相关性，但不能靠它确定某个错误的原因。此节用于限定结论，不以“发现污染”作预定卖点。

### D. 重复性：看到的变化是否稳定？

在代表子集上固定输入，记录采样设置并重复调用；比较单次、重复分布和多数投票。Greedy 本地模型重复同输入通常不会产生有意义的采样分布。
模型生成随机性不等于人的感知分歧；若研究两者关系，要控制类别比例，并与简单类别先验等基线比较。
`token_p_*` 只是首 token 的标签分数代理，不能直接替代重复生成的答案分布。
按说话人或对话分组估计配对变化的区间，避免把同一对话的很多句当作完全独立样本。不能仅凭不显著就宣布方法无效。

### E. 文字对照：帮助来自什么内容？

对照目标句转写和过去轮次转写。区分人工转写（较理想的语义条件）与 ASR 转写（包含识别错误）。
模型利用文字并不自动是错误：对话情绪本来就可能依赖语义。它限制的是“收益来自声音信息”的结论。
先在 pilot 需要的样本上做，不预设全部 13 个语料都跑一遍 ASR。

### G. 标签：评的是表演要求，还是听者感知？

同一条声音的演员指定情绪与听众感知可能不同。对有投票的语料，按相同目标分别计分，报告分歧、类别分层及 neutral 基线。
不能因为模型常答 neutral，就在听众多选 neutral 的子集上宣称更像人。MELD 标签涉及视频和转写，不能当纯音频听众票；
也不能把其他语料一概称为只有演员标签。A2 的多证据条件人类投票是新增材料，尚不存在于现有导出里。

### F / H. 可选：线性 probe、标签分数与校准

[线性 probe 脚本与说明](../../emotion_recognition/scripts/analysis/README.md)已实现：冻结保存向量，用有标签训练集教一个小线性分类器，
只根据验证集选择 C 和层，再看测试集。它能检查这些表示是否支持监督线性预测，不能定位原生成失败的原因。
它不是零样本成绩，也不能证明“模型已经听懂，只是最后一层错了”。当前将其列为可选辅助分析或附录，不因已有代码就必须跑完所有组合。

`probe_p_*` 是新分类器的概率；原 LLM 的 `p_*` 是回答的 one-hot；`token_p_*` / `token_mass` 是首 token 代理。
校准和先验校正需要另定规则与独立数据；先验校正尚未实现，不能先假定每个标签理应等概率。
API logprobs 的已核查边界见 [api_logprobs.md](api_logprobs.md)。模型和接口可能更新，正式执行前再核对。

### I / J / K. 暂缓与局限

JEV 式结构化输出、电话编码不纳入本轮；背景分别见 [jev_analysis.md](jev_analysis.md) 和旧设计。
记录长度、裁切、padding、背景声和多说话人；长历史不能被某模型静默截断后还当相同输入比较。

## 8. 什么结果才值得写成论文？

优先寻找能改变我们理解的证据，而不是仅多一张性能表。例如：

- 同说话人参照有效，但相同标签、不同说话人的参照无效：支持个体声音基线的作用。
- 人能从真实历史获益，模型却没有相应变化：限定当前模型利用对话证据的能力。
- 模型与人的变化一致，但收益可由文字历史解释：应把贡献放在语义上下文，而非纯声学改善。
- 某种改善在第二个语料和不同模型中复现：比只在开发集涨分更有说服力。

这些仍是候选结果。若 pilot 只是重复普通 ICL 无效，或区间太宽无法区分解释，就停止扩大、修改问题或暂缓该方向。
负结果需要清楚的比较对象、足够精度和有意义的能力边界，不因“做了对照”就自动构成贡献。

**暂定标题**：*What Context Helps Audio LLMs Judge Emotion?*；*Speaker References or Dialogue History? Studying Emotion Judgments in Audio LLMs*。
标题和最终 RQ 应随发现收敛。不要先把 A、B、C、D 各写成一项已经成立的贡献，也不预承诺录用层级。
